# 個人用ダッシュボード ── 話す・調べる・整理する

> 「やるべきことを忘れる」「調べたことが散らばる」「日々の振り返りが続かない」

##　使い方

`index.html` をブラウザ（Chrome推奨）で開くだけで動作します。インストール不要。

- 音声入力は Chrome の Web Speech API を使用しています
- データはブラウザの localStorage に保存されます（リロードしても消えません）

---

## 何を作ろうと思ったか・なぜか

自身の考えなど気になったこと、アイデアになりそうなものをまとめるメモ帳のようなもの

日々のタスク管理だけではなく、長期目標とのつながりを感じる必要性を感じた。
また、一日を振り返る機会を作ることで目標が明確でない時期を減らしていきたい。
その場でメモをしたはいいがどこにメモをしたか忘れてしまう。

## 🛠️ 機能一覧

| 機能 | 説明 |
|---|---|
| **目標ツリー** | 長期目標 → 今年 → 今月 → 今週を階層表示。つながりが一目でわかる |
| **今日のタスク** | チェックボックスで完了管理。音声入力対応 |
| **知識メモ帳** | タイトル・内容・複数ラベルでカード保存。日時順／あいうえお順で並び替え、AND絞り込みに対応 |
| **思考メモ** | 自由記述＋音声入力。過去のメモを一覧表示 |
| **日報（3ステップ）** | 完了・未完了タスクを自動入力 → 自由記述 → 明日のタスク登録 → 保存・コピー |
| **起動時の進捗確認** | 未完了タスクをバナーで通知 |
| **17時の自動日報** | 17時になると日報ページが自動で開く |

## 🤖 生成AIとのやり取り

### 開発の進め方

このアプリはコードを1行も手書きせず、**Claudeとの対話だけで作った**。  
手順はシンプルで、以下のサイクルを繰り返した。

```
① 「不便に思っていること」を話す
② Claudeが機能に翻訳してくれる
③ 「こうじゃなくてこう」と修正指示
④ 動くコードが出てくる
⑤ また①へ
```

### 実際のプロンプトの流れ（抜粋）

**最初の設計段階**
```
「やること、調べること、ネタの文字起こし、長期・短期の目標管理、
 やるべきことをすぐ動けないことが不便。これをまとめて解決したい。」
```
→ Claudeが機能を整理・提案し、3ページ構成に絞り込んだ。

**機能の詳細化**
```
「マイクで話した内容を別ページに蓄積して、
 ラベルでフィルタリングしたい。政治家ラベルだけ見るとか。」
```
→ 知識メモ帳のカード＋タグ設計が決まった。

**UX改善の指示**
```
「ラベルの入力と貼る場所は別がいい。
 エンターでどんどん追加していく感じにして。」
```
→ 入力欄とチップ表示エリアを分離。

**日報の設計**
```
「自分で書き込めるようにしつつ、
 タスクは自動入力されていてほしい。
 入力が終わったら明日のタスクを作る流れを作りたい。」
```
→ 3ステップの日報フローが生まれた。


## 詰まったところとどう乗り越えたか

### ラベルのUI設計

**問題：** ラベルのイメージを言葉に表すのに時間を要した。どのようにAIに投げればイメージ通りに返ってくるのかを試行錯誤した。

**解決：** Claudeに「入力欄とラベルを貼る場所を分けて、Enterでどんどん追加していく感じにしたい」と自分のイメージを言葉にして伝えた。するとタグチップUIとして実装してもらえ、使いやすくなった。

→ **教訓：中身に対する知識があれば表現を変え、スムーズに作成できたと思う。

## 🔭 次にやるなら何を変えるか

### 1. UIの改善
目標ツリーやカード表示をより視覚的に洗練させたい。アニメーションや色のコントラスト調整など。

### 2. ラベルの多次元可視化
「重要度」「面白さ」など尺度のあるラベルは、数直線・平面・立体で表現したい。例えば「重要度×緊急度」の2軸マトリクスでカードを配置するなど。

### 3. スマホアプリ化
音声入力を使う場面はスマホのほうが自然。常に手元にあるため入力漏れが減る。
